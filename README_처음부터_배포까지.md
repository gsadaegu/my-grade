# 이거 내 학점이야 🤨 — 처음부터 무료 배포까지

이 프로젝트는 **HTML/CSS/JavaScript로 만든 GitHub Pages용 정적 웹사이트**와 **Supabase 데이터베이스 SQL**로 구성됩니다. GitHub와 Supabase 계정 생성 및 연결은 사용자가 직접 해야 하며, 지금 상태로는 공개 URL이나 실제 저장 데이터가 아직 없습니다.

## 포함된 파일
- `index.html` — 학점 입력, 결과, Gemini 가입 안내와 프롬프트
- `style.css` — 기존 화이트·블루 디자인
- `app.js` — 학교 검색, 4.3 자동 비례 환산, 표정 변화, 통계 요청
- `assets/` — 카피바라 표정 4종 + Team Gemini 로고
- `schools.json` — **기존 시안에서 가져온 258개 학교 시작 목록** (전국 전체 학교 목록이 아님)
- `config.js` — Supabase 프로젝트 URL과 공개 키를 입력하는 설정
- `supabase.sql` — 학점 저장, 삭제, 학교별/전국 통계 RPC와 권한 설정

## 1. GitHub Pages에 올리기
1. https://github.com 에서 계정을 만듭니다.
2. `New repository`를 눌러 공개 저장소(예: `my-gpa`)를 만듭니다.
3. 압축파일을 풀고 **안쪽 파일과 assets 폴더**를 저장소 최상위(루트)에 업로드합니다. ZIP 파일 하나만 올리는 것이 아닙니다.
4. 저장소 `Settings` → `Pages` → `Build and deployment`에서 `Deploy from a branch`, `main`, `/(root)`를 선택하고 저장합니다.
5. 안내되는 `https://계정명.github.io/my-gpa/` 주소로 접속합니다. 배포 반영에는 시간이 걸릴 수 있습니다.
6. `config.js`가 비어 있으면 사이트는 **시연 모드**로만 동작합니다. 이는 정상이며, 통계가 저장되었다고 표시하지 않습니다.

## 2. Supabase 데이터베이스 만들기
1. https://supabase.com 에 로그인하고 `New project`를 만듭니다.
2. 대시보드에서 `SQL Editor` → `New query`를 열고 `supabase.sql` 내용을 전체 붙여넣어 실행합니다.
3. `Authentication` → `Providers`에서 **Anonymous Sign-Ins**를 활성화합니다. (설정 메뉴 이름은 버전마다 달라질 수 있습니다.)
4. `Project Settings` → `API`에서 **Project URL**과 **publishable key** (또는 공개용 anon key)를 확인합니다.
5. `config.js`의 `supabaseUrl`과 `supabasePublishableKey`에 각각 붙여 넣고 GitHub에 저장(commit)합니다.
6. **절대로 service_role 키나 secret 키를 config.js, GitHub, 클라이언트 코드에 넣지 마세요.**
7. GitHub Pages 사이트를 새로고침합니다. 학교를 선택하고 학점 입력 → 저장 동의 선택 → 위치 확인을 진행해 테스트합니다.
8. Supabase `Table Editor`에서 `grade_entries`에 데이터가 한 건 생성되는지 확인합니다. 다시 입력하면 같은 익명 사용자 기록이 갱신돼야 합니다.
9. `내 저장된 학점 삭제하기`를 눌러서 원본 데이터가 삭제되는지 확인합니다.

## 3. 실제 비교가 표시되는 조건
- **동의하고 저장한 참여자**만 통계에 반영합니다.
- 전국/선택한 학교 범위에서 **30명 이상**일 때에만 참여자 기준 평균 및 대략적인 상위 백분위를 표시합니다.
- 30명 미만이면 `준비 중` 안내와 점수 기반 **시연용 위치**만 표시합니다. 전국 대학생 전체 학점 분포를 뜻하지 않습니다.
- 학교 정보를 직접 선택하는 방식이어서 학교 재학 여부는 검증되지 않습니다.
- 익명 로그인을 이용해 같은 브라우저 사용자별 기록을 덮어쓰지만, 다른 기기·브라우저로 중복 참여하는 것을 완전히 막지 못합니다.

## 4. 공개 배포 전 반드시 할 일
1. **학교 전체 목록 완성:** 지금의 258개 내장 목록은 불완전합니다. 공공데이터포털의 전국대학및전문대학정보표준데이터 및 최신 교육부 학교 정보를 검증해 `schools.json`에 학교 ID·캠퍼스 식별 기준까지 반영하세요. 현재 이름 기반 식별이므로 동명이교/통합 학교 문제를 보완해야 합니다.
2. **익명 로그인 남용 방지:** Supabase 공식 가이드에 따라 CAPTCHA/Turnstile, 적절한 요청 제한, 모니터링을 활성화하세요. 이 SQL은 기본 RLS 및 RPC 격리 예시이며 대규모 공개용 보안 점검을 대체하지 않습니다.
3. **개인정보/운영 안내:** 누가 어떤 정보를 수집하는지, 보관 기간·삭제 문의처·통계 활용 등을 실제 운영 주체에 맞게 안내하세요. 현재의 동의 체크박스와 삭제 기능은 출발점입니다.
4. **학점 검증:** 성적증명서 등으로 확인하지 않으므로 허위 기재와 표본 편향 가능성이 있습니다. 진짜 학교·전국 순위를 보장한다고 홍보하지 마세요.
5. **Gemini 혜택:** 외부 링크는 https://cutly.kr/41im0d 이며 학생 혜택 조건이 변경될 수 있으므로 공식 페이지 문구와 일치하는지 공개 전 확인하세요. 클릭 수는 실제 가입 완료 수와 다릅니다.
6. **분석:** GA4 `gtag`를 별도 설치할 경우 모든 가입 버튼에서 `gemini_signup_click` 이벤트를 보내도록 준비돼 있습니다. 지금은 `console.info`만 남기며 사이트에 클릭 수를 저장하지 않습니다.
7. **브라우저 테스트:** 모바일에서 학점 유효성, 4.3 환산, 학교 검색, 팝업, 데이터 저장/삭제, 노션 2개, Gemini 가입 링크를 점검하세요.

## 테스트 예시
- 학교: 대구대학교, 학점 기준: 4.3, 학점: 3.70 → 결과 화면에 약 **3.87 / 4.5** 표시
- 학점 기준 4.5에서 4.6 입력 → 진행 버튼 비활성
- 학교 검색 목록에서 선택하지 않은 값은 제출할 수 없음
- 학교별 참여자가 30명 미만 → 실제 상위 %를 보여주지 않음

## 현재 프로젝트의 한계
- GitHub Pages에 직접 배포하거나 Supabase 계정을 생성·연결한 상태는 아닙니다.
- 학교 데이터는 전국 **완전 목록이 아닌 258개 시작 목록**입니다.
- 이미지/시각화는 실제 서비스에 적용할 수 있지만 데이터 검증 및 통계 정책은 운영 전에 추가 검토가 필요합니다.
- GitHub Pages와 Supabase 무료 한도는 각 서비스의 현행 약관과 정책을 확인하세요.
